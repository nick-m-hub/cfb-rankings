This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

CFB Rankings (`package.json` name: `cfb-rankings`) is a public FBS power ranking that blends a best-team (predictive) model and a most-deserving (resume) model with a user-controlled slider. **[docs/phase1_spec.md](docs/phase1_spec.md) is the source of truth** for the original scope; read it before starting any feature. It also lists open decisions (see below) — stop and ask rather than guessing new ones.

Built and working (2026-11-05): CFBD client, team-name crosswalk, ingest/backfill, compute, weekly cron, and these pages: `/` (redirects to `/rankings`), `/rankings` and `/rankings/[season]/[week]` (slider table), `/methodology`, `/stats` (sortable table of every team's stats), `/blind` (blind ranking game). Backfilled 2014–2026 week by week. Still open: final site name/domain (placeholder in `lib/site.ts`).

Methodology review (2026-11-05, goal: as unbiased as possible). Done: preseason prior fades by games played; resume model rates opponents leave-one-out; FCS teams rated individually (FCS-vs-FCS games now stored); schedule strength uses the resume benchmark (12th-best team); crowd votes capped per session; 2013 FPI stored so 2014 has a prior. Considered and **rejected on evidence** (don't redo without new data): rating opponents for schedule strength / best win with results-only ratings (13.53-point walk-forward miss vs 12.73; 12.86 vs 12.69 even from week 10), dropping recruiting talent from the prior (week 1–3 miss 13.34 vs 13.07), dropping the prior entirely. Also rejected (2026-11-16): a lower best-team margin cap (walk-forward 2016–2025, FBS-vs-FBS from week 2: cap 21 / 28 / 40 / none with half credit beyond = 12.73 / 12.72 / 12.71 / 12.71 after rescaling for `slope`; cap 40 best or tied in 6 of 11 seasons; 2026 alone favors 21 by 0.1; no tail credit beyond the cap is worse at every cap). Checked and fine: the z-score blend (top-25 z spreads 1.25 vs 1.16, so slider 50 is balanced). Still open, disclosure only: the resume score is a sum, so teams with an extra game or a bye differ by ~0.1–0.2 credit per game mid-season.

## Working rules

- Read `docs/phase1_spec.md` before starting any task.
- This project is standalone: never reference, import from, or touch other repos, folders, or databases (the spec's mention of another project's stack is background only; don't act on it).
- Original build order (done): migrations → CFBD client → crosswalk → backfill → compute → cron → pages.
- Open decisions, resolved 2026-11-03: site name is the placeholder "CFB Rankings" (final name/domain still TBD, keep it in one constant); slider default 50; FCS teams hidden entirely (still count FCS opponents in records); CFBD stays on the free tier (1,000 calls/month, shared pool), so the backfill must cache raw responses on disk and be re-runnable at zero API cost. (The spec's SP+/FPI/Elo/SRS split was superseded 2026-11-05, see Models.)
- CFBD history (verified 2026-11-03): only `/ratings/elo` honors `week`. SP+, FPI and SRS ignore it, so backfilled weeks use end-of-season values (look-ahead) and the weekly cron snapshots them going forward. Disclose this on `/methodology`.
- Week convention: CFBD restarts postseason at week 1; store postseason as (last regular week + 1).
- Migrations are applied by hand in the Supabase SQL editor (no `supabase` CLI or `psql` here). When you add one, say so and give the user the file; the app errors until it is applied. After a schema change that adds ingested columns, re-run `npm run ingest-current -- --all-weeks` (current season, spends CFBD calls) or `npm run backfill` (history, zero API cost from the disk cache), then `npm run compute`.
- Avoid native dialogs (`window.confirm` etc.): the in-app browser blocks them. Use inline two-step confirms.

Required env vars (copy `.env.example` to `.env.local`): `CFBD_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (server/scripts only), `CRON_SECRET`, `REVALIDATE_SECRET`.

**Dev cache gotcha:** `getWeekData`/`getBlindData` use `"use cache"` with `cacheLife("max")` and the `rankings` tag. Scripts (ingest/compute) write the DB outside Next, so a running dev server keeps serving stale data until restarted. The cron route calls `revalidateTag` itself.

## Architecture

- **Stack**: Next.js App Router + TypeScript + Tailwind, Supabase Postgres (new, dedicated project), Vercel hosting. Every piece of infrastructure is its own instance.
- **Layout**: `app/` pages and API routes; `components/` UI; `lib/cfbd/` API client and typed responses; `lib/ingest/` shared ingest; `lib/compute/` pure normalization/composite functions; `lib/models/` the two in-house models and schedule strength; `lib/blind/` blind-ranking math and data; `lib/rankings/` slider data/ranking; `supabase/migrations/` SQL; `scripts/` backfill and one-offs. Pure logic is unit-tested (`lib/**/*.test.ts`).
- **Ingest**: one shared ingest module used by both the Vercel Cron route (`/api/cron/ingest`, protected by `CRON_SECRET`, Sunday and Wednesday 10:00 UTC) and the local backfill script (local to avoid serverless time limits). All writes are upserts so re-runs are idempotent. Unmatched team names must fail loudly and be reported, never silently dropped.
- **Data model**: ratings are stored long (one row per system/team/season/week) so new rating systems need no schema change. Tables: `teams` (FBS plus every FCS team in a stored game), `team_aliases` (name crosswalk), `systems`, `ratings` (incl. 2013 FPI rows, used only as 2014's prior), `games` (incl. `home/away_postgame_wp`; also FCS-vs-FCS games since 2026-11-05, so code reading `games` for FBS purposes must filter by FBS membership, as records and blind stats do), `committee_ranks`, `composite_scores`, `team_seasons` (FBS membership per season), `game_team_stats` (plays, success rate, `off_ppa`, `def_ppa`, `def_plays`), `team_season_inputs` (returning production, talent), `model_details` (jsonb per team/week), `blind_votes`. RLS: public read on `teams`, `systems`, `composite_scores` only; everything else (incl. `blind_votes`) is service-role only.
- **Compute**: the in-house models run first for each week (`lib/models/run.ts`), then per-system, per-week z-scores across that season's FBS teams, sign flipped for lower-is-better systems, no imputation. Composites use only `in_composite` systems: predictive = Best-Team Model, resume = Resume Model. Each composite is re-standardized across FBS before blending. Blend `s·z_pred + (1−s)·z_resume` runs client-side only (0 = most deserving, 100 = best team).
- **Frontend**: `/rankings` and `/rankings/[season]/[week]` are static per week, revalidated on demand after ingest (no time-based revalidation). The slider value lives in the URL (`?blend=70`). `/methodology` explains the inputs; keep it in sync when behavior changes. Mobile-first.
- **API routes**: `/api/cron/ingest`; `/api/blind/vote` (POST), `/api/blind/results` (GET, after `connection()`), `/api/blind/names` (GET, exactly three ids).
- **Phase boundaries**: learned weights, backtesting, margin caps and game grades are Phase 2 (new `model_weights` table); don't add schema or code for them now, but don't make choices that would require migrating existing tables.

## Models (`lib/models/`)

- 2026-11-05 (Nick): the slider is driven by two in-house models ported from the CFB Fun notebook: a **resume model** ("most deserving") and a **best-team model** v2 (predictive). SP+, FPI, Elo and SRS stay ingested as reference systems (`systems.in_composite = false`) shown in team details, not in composites. Outputs go into `ratings` (raw_value) plus `model_details`. Each week uses only games through that week.
- **Resume** (`resume.ts`): rates teams from this season's margins capped at 21 (ridge, fitted home field, FCS teams rated individually, no prior); each game's credit = result − chance a benchmark team (12th-best rating) wins at that site; score = sum of credits. Opponents are rated **leave-one-out** (refit without the team's games, 2026-11-05) so a team's own margin never matters; the benchmark stays the full fit's 12th-best. Top-12 odds simulate the full fit's covariance and shift each team by its leave-one-out adjustment.
- **Accuracy** (walk-forward, FBS-vs-FBS games, week 2 on, current settings): 12.0-point average miss and 70% of winners in 2026 (out of sample), 12.4 / 72% in 2023–2025, 12.9 / 72% in 2016–2022 (tuning seasons, slightly flattering). `/methodology` quotes these; update them if the model changes.
- **Best team** (`best.ts`): opponent-adjusted margin ridge regression (full credit to 40 points, half beyond; 85% score / 15% success-rate gap), fitted home field, FCS teams rated individually, preseason prior (last FPI, returning production, talent) worth 6 games that **halves every 6 games a team plays** (`priorHalfLife`; 2026-11-05 walk-forward: same accuracy as the notebook's constant 4, less reputation late in the season; no prior is much worse even late, and dropping talent hurts early weeks, so both stay). `slope` was refit for the faded prior. It is margin-based, not win/loss based: a 1-8 team with close losses to a hard schedule can outrate a 4-5 team. Ratings are only good to a few points (~4 mid-season), so don't read fine rank differences as meaningful. The overall fit is also exposed as `computeBestRatings` (cheap, reused per team by schedule strength).
- Parameters are constants in those files. `models.test.ts` checks the code against a golden 2026 fixture from the Python reference **using the notebook's settings** (`REFERENCE_BEST_PARAMS`; resume with `leaveOneOut: false, fcsRidge: Infinity`), so retuning the defaults doesn't need a new fixture but refactors must keep that test green.
- **FCS teams** (`design.ts`, `fcsRidge` 2 in both models): each FCS team's rating = FCS pool + an offset ridge-shrunk toward the pool, fit from FBS-vs-FCS and FCS-vs-FCS games (FCS-vs-FCS home field is its own column). Ingest stores FCS-vs-FCS games (`storedGames`; D-II/III-only games dropped). Walk-forward: FBS-vs-FCS miss 13.6 vs 14.8 pooled. `fcsRidge: Infinity` restores the single pooled FCS team.
- **Tuning harness**: walk-forward tests were run from scratch scripts (2016–2025, predict week w from games before w); if you retune, rerun that kind of test, don't eyeball.
- **Schedule strength** (`sos.ts`, stored as `model_details.details.sos = { winPct, rank }`): how often the resume benchmark team (12th-best rating in the fit, excluding the team itself; was "an average FBS team" until 2026-11-05) would win each team's games so far (lower = harder; rank 1 = hardest). Opponents are rated by best-team ratings **refit without any of the team's own games** (leave-one-out, so beating someone doesn't make your own schedule look easy), converted to a win chance with sd 15.5 (= 12.4 average miss × √(π/2)) plus home field. FCS opponents use their individual rating from actual results (no stand-in value). Replaced an Elo-average version that rated every FCS opponent at the lowest FBS Elo and so penalized FCS games arbitrarily. The prior still informs opponent ratings (it rates opponents more accurately than results alone; see Project state).
- **Best win / worst loss** (`bestWinWorstLoss` in `resume.ts`, stored in `model_details.details.resume` with `opponentId`): the best team beaten / worst team lost to by best-team rating (what the labels mean to readers, Nick 2026-11-05). Opponents within `RATING_TIE_TOLERANCE` (4 points) of the extreme are tied and the opponent's record decides (better record = best win; worse = worst loss). Site and margin never matter. This is the single source for the rankings page and stats page (blind cards show quadrant records instead). Ties on the scoreboard count as neither.
- `model_details` jsonb is read by `lib/rankings/data.ts`; fields added later (`sos`, `opponentId`) are optional in `ModelDetails` because older weeks lack them until `npm run compute` is re-run.

## Blind ranking (`/blind`, `lib/blind/`, `components/BlindRanking.tsx`)

- Visitors rank three anonymous team cards (1st/2nd/3rd) from the **current season's latest week**; ~15 rounds unlock a personal ranking of every FBS team, and all votes feed a **crowd ranking that resets every Monday 00:00 Eastern** (`crowdWeekStart`; votes keep `crowd_week`, old votes are kept; crowd shows after 200 votes that week).
- **Card stats** (all derived from stored data, built in `getBlindData` in `lib/blind/data.ts`): record; avg margin; offense and defense EPA/play ranks (CFBD "PPA", play-weighted, from `game_team_stats`); average postgame win probability (CFBD's proprietary estimate from efficiency, not the score; averaging across games is our choice); record vs. opponent quadrants Q1–Q4 (model features: Q1 wins and Q3+Q4 losses). Schedule strength and best win/worst loss were removed from the cards 2026-11-06 (Nick) and stay on `/stats` and the rankings page; `BlindCard` still carries them for `/stats`. **Our model ranks (Resume Rank etc.) are deliberately not on the cards**, and a stat the voter can't see must not be a model feature (features in `features.ts` mirror the card stats; missing values are mean-filled).
- **Quadrants** (`computeSchedule` in `lib/models/sos.ts`, stored as `model_details.details.quadrants`): home bands are opponent ranks 1–15 / 16–40 / 41–75 / 76+ of 136 FBS (`HOME_QUADRANT_RANKS`, Nick 2026-11-06), scaled to the FBS count; opponent ratings are site-adjusted by the fitted home field, so neutral/road bands reach further down (typically ~21/52/85 and ~33/63/100), like NET. Opponents rated leave-one-out (same fit as schedule strength); FCS opponents placed by their own rating; scoreboard ties excluded. Considered and rejected: equal quartiles (Q1 too broad), cutoffs on a top-12 team's win chance (band sizes swung ~2x between seasons with rating spread).
- **Model** (`fit.ts`, `model.ts`): Plackett-Luce on ranked triples with strength = stat weights · z-scored stats + a per-team offset (L2-shrunk). Until a voter's own rounds say otherwise it shrinks toward default weights (`DEFAULT_STAT_WEIGHT` 0.6, strength 1 in `constants.ts`): chosen by simulation so 15 rounds is usable; a stronger pull (3) hurt contrarian voters, so don't raise it. The next cards are picked for information (`pick.ts`: close calls whose stats differ most), not just coverage. Simulated agreement ~0.78 at 15 rounds vs ~0.66 for the plain fit.
- **Privacy/blindness**: names never ship with the page. `/api/blind/names` returns only the three teams just ranked (for a ~1.4s flash on the cards). It queries `teams`/`team_seasons` directly (FBS in the newest season) instead of `getBlindData`: a cold server takes ~5s to rebuild the cards, which exceeded the client's timeout and silently dropped the names (fixed 2026-11-05; client timeout now 5s). Keep it off `getBlindData`; `/api/blind/results` returns names plus the crowd ranking after the visitor opens results. Rounds can't be redone (no undo, taps ignored while a round is locked); "Start over" is a two-tap confirm.
- **Storage and abuse**: votes are saved in the browser (`localStorage` key `blind-votes:<season>`) and posted to `/api/blind/vote`, which validates ids against the current cards, sets an httpOnly `blind_session` UUID cookie, rate-limits per session (1 vote/sec, 500/day, checked against `blind_votes`) and writes with the service role. The crowd ranking is cached ~minutes (`CROWD_TAG`). Crowd votes are capped per session (`CROWD_SESSION_CAP` = 40 votes' worth, `sessionWeights` in `model.ts`); the 200-vote threshold counts capped votes. The session cookie is easy to reset, so the cap limits casual flooding, not determined abuse.
- **G6-only mode** (2026-11-06, Nick): a toggle on `/blind` (remembered in `localStorage` key `blind-g6`) plays only G6 teams (`isG6` in `lib/g6.ts`, shared with the `/rankings` G6 toggle `?g6=1`: American, C-USA, MAC, Mountain West, Sun Belt, the Pac-12 from 2026, plus UConn; G6-only records are in `lib/blind/g6.ts`). The card record, avg margin and postgame win probability become `g6Record` / `g6Margin` / `g6PostgameWp` (decided games vs other G6 teams, ties skipped like the all-games stats), and so do the model's matching features; other stats are unchanged. G6 rounds use their own key (`blind-votes-g6:<season>`), unlock "See my G6 ranking" at 15 rounds, and are **never posted** to `/api/blind/vote` (personal only; they'd skew the crowd since the record stat differs). The mode is a remount of `BlindGame` keyed on the toggle.
- **Your blend** (2026-11-16, Nick; `lib/blind/blend.ts`, `matchBlend`): the results view shows where the voter's picks sit on the `/rankings` slider. It scores the **raw votes** (not the fitted ranking, which leans on default weights at 15 rounds): for each s in 0..100, a 1-D Plackett-Luce fit of strength k·`blendScore(s)`; the blend is the max-likelihood s, the range is everything within 1.92 log-lik (~95%). The z-scores come only in the reveal (`BlindTeamInfo.zPred/zResume` via `/api/blind/results`), never on cards. The crowd blend (`CrowdRanking.blend`) is the same over the week's votes with `sessionWeights`, null below the 200-vote threshold, main mode only.
- `/stats` (`components/StatsTable.tsx`, `lib/blind/table.ts`) shows every team's stats with names and our Resume/Best ranks in a table sortable by header (best-first on first click, nulls always last).
